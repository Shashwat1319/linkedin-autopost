Docs aren't for others. They're for you in 6 months.

My minimum README for ANY project:
→ What it does — one paragraph, no buzzwords
→ How to run it — copy-paste blocks (I copy mine and it WORKS)
→ Environment variables — a table, not "set up config"
→ What's inside — the interesting decisions and why
→ What I'd do next — honest roadmap

Why I bother: every time I return to a project, I re-derive all of it anyway. Writing once = thinking once.

Plus: a recruiter who opens your repo decides in 20 seconds whether you're organized.

Docs are code's first impression.
